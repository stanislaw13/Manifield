Approach ontology — the space you are sampling from. Use it as a coverage checklist, not a menu to copy: name the cells each approach occupies, and name the high-value cells you are deliberately leaving out.

Tactic families:
- direct / inductive — build the result step by step, or induct on a natural parameter.
- extremal — assume a minimal or maximal counterexample and derive structure from its minimality.
- probabilistic — random construction, first/second moment, concentration; existence without construction.
- algebraic reformulation — recast the problem as algebra (polynomials, groups, matrices, generating functions).
- computational search — exhaustive or heuristic search over small cases; the cheapest decisive test.
- reduction / transfer — reduce to a solved problem, or transport it into a field where the tools are stronger.
- counterexample construction — build the object the statement forbids; the fastest way to end a false conjecture.
- asymptotic vs exact — attack the limiting behaviour instead of the exact bound, or the reverse.

Research lenses — a lens is a standing prior about what is true and where the answer lives. Pick lenses that genuinely disagree with each other. Several are phrased for a statement to be settled; where the problem instead asks for a value, an object or a classification, read them against the *leading candidate answer* — the Refuter attacks the candidate rather than a conjecture, and the Skeptic-of-Framing doubts the model of the problem rather than the statement:
- Constructor — the object exists; build it explicitly.
- Refuter — the leading answer is wrong; attack it. Against a statement that means hunting a counterexample; against a proposed value it means beating that value or breaking its optimality argument; against a claimed classification it means finding the case it misses.
- Minimalist — the hypotheses are too strong; find the smallest ones that still work.
- Bridge-Builder — this is an instance of something known in another field; find the dictionary.
- Generalizer — the general case is easier than the special one; abstract until the obstruction disappears.
- Specializer — solve one hard concrete case completely; the general proof will follow the same shape.
- Probabilist — the extremal objects are rare; a random one almost surely works.
- Computer — compute first, conjecture from the data, prove last.
- Skeptic-of-Framing — the definitions are the bug; the right statement is a nearby one.
- Historian — someone nearly solved this; find the closest prior attempt and finish it.

Rules:
- Approaches must occupy distinct cells; four flavours of the same induction is one approach, not four.
- Include contradictory pairs, in whatever form the problem admits. Against a statement, one route assumes it is TRUE and another that it is FALSE. Where the answer is a value or an object, routes should reach it by genuinely different mechanisms — ones that could disagree, so their agreement is worth something — with one attacking whatever answer leads. A portfolio that only looks for confirmations reproduces the failure this whole mechanism exists to prevent.
- Where the answer is a value or an object, prefer routes independent enough to cross-check each other: an exact/variational route and a numerical route that must agree is worth far more than two analytic routes sharing an assumption.
- Every high-value cell you skip must be listed with an honest reason.
